### P1-bot-taktik finished. Existing bot systems were extended, not rebuilt. The final verify run was `verify.sh --player --tests`: 0 errors in all assemblies including the player build, 1348 passed, 0 fa
  - The bot model has no lean animation. Peeking from tall cover is a sidestep to the cover's corner point, and from low cover it is standing up. A real lean pose would need a SoldierModel hook, which is outside this scope. ENTEGRASYON: Characters/SoldierModel: add a lean pose hook if one is wanted.
  - Bullet near-miss suppression only reaches bots, through the ray-proximity check in `SuppressAlongShot`. Player shots suppress bots only through the gunfire-hearing path, which applies only while a bot is in contact (seen an enemy within 3 s). `BallisticsSystem.NearMiss` only reports the local player's head. ENTEGRASYON: Combat/BallisticsSystem: an event with the bot's `Combatant` on a near-miss would give exact suppression from player fire.
  - Bot reaction time is now set in `BotController.Setup`, overriding the 0.3–0.9 s values in `BotDifficultyProfile` (Application/Services) for each bot. The profile file is unchanged, and Easy bots are now faster than before (0.45 s at most instead of 0.9 s). Also, because `ConfigureSkill` makes extra RNG draws, a given seed produces a different bot individual than before.
  - The footstep and gunfire occlusion rays use `GameLayers.LineOfSightMask`. Terrain and walls count as blockers; I assumed that mask does not include character layers, which looks right from how `HasLineOfSight` uses it.
  - The headless verify could not run physics, `NavMesh` or `DialogueDirector`. Peek timing, cover finding and radio callouts are unverified in play. Test coverage is on the pure rules only.
  - Added `ClearCover()` calls and a latched-cover state. A bot that leaves Engage while in cover loses its peek state, and cover is held for the tactic timer of 3–8 s (the old early-leave rule is removed). Worth a short in-game check that bots don't stay in cover too long.
  - `DialogueDirector.Say` returns false when the clip book is missing or the category has no lines, so some callouts may be silent until the dialogue book has entries for those categories.
